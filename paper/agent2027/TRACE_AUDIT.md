## Source-code checks

- [commit-timeout task configuration](../../tasks/commit_timeout/task.toml) explicitly transfers `/state/trustval.db` from sidecar as verifier artifact, isolates the agent and verifier environments, and permits only specified network destinations.
- [commit-timeout reference](../../tasks/commit_timeout/solution/solve.sh) reads `ledger` before and after ambiguous writes. Unlike a transaction-based exactly-once guarantee, it depends on the visibility of the queryable state.
- [partial-batch reference](../../tasks/partial_batch/solution/solve.sh) reserves items **one by one** and never invokes `reserve-batch`, so its success does not establish that the injected batch fault is recoverable by the reference solution.
- [regrade implementation](../../scripts/regrade.py) locates exported SQLite state artifacts, substitutes their path into each `tests/verify.py`, and executes the verifier. The scores in tracked run `regrade.json` are not generated from the agent's final prose.

## Remaining scientific verification

- Binary SQLite artifacts were not accessible from the linked GitHub contents path, so direct independent SQL inspection remains **open**. The trace's authoritative API ledger and saved regrades support the specific failure examples.
- A five-sample spot check is **not** an independent re-audit of all 26 manually classified Claude 4.x failures. The entire classification is currently sourced from [RESULTS.md](../../RESULTS.md), whose claims must be labeled as such.
- The same four tasks repeated across ten runs are correlated within each run and do not establish transfer to unseen environments. The exact run-level permutation calculation supports the reported fixed-scenario contrast only.

**Editorial consequence:** replace broad wording like "we independently re-audited all 26" with "the run ledger classifies all 26; spot checks of original trajectories support representative failure mechanisms." Avoid saying the reviewer directly read all SQLite binaries.
